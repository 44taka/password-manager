## 0. 基本原則

実装を開始する前に、以下のドキュメントを必ず確認し、これらに従った設計・実装を行ってください。

- **ADR (Architecture Decision Records)**: `docs/adr/` 配下に記録されたアーキテクチャ上の意思決定を遵守すること。
- **ユビキタス言語**: `docs/ubiquitous_language.md` で定義された用語を使用し、モデルや変数名に反映させること。

## 1. TDD サイクル (RED → GREEN → REFACTOR)

以下のサイクルを最小単位として、機能を積み上げていきます。

### 🟥 STEP 1: RED (テスト駆動)
- **行動**: 実装したい機能に対するテストを先に書く。
- **期待**: 実装が存在しない、あるいは不完全なため、テストが失敗する。
- **コマンド**:
  ```bash
  # 特定のテストファイルを実行
  uv run pytest tests/path/to/test_file.py

  # 特定のテストケースのみ実行
  uv run pytest tests/path/to/test_file.py -k "test_function_name"
  ```

### 🟩 STEP 2: GREEN (最小実装)
- **行動**: テストをパスさせるための**最小限**のコードを書く。
- **期待**: テストがパスすること。
- **注意**: この段階では「汚いコード」でも構わない。まずは動くことを優先する。
- **コマンド**:
  ```bash
  make test
  ```

### 🟦 STEP 3: REFACTOR (改善)
- **行動**: テストが通る状態（GREEN）を維持したまま、コードを整理・改善する。
- **ポイント**: 重複の削除、命名の改善、関数の抽出、依存関係の整理。
- **期待**: リファクタリング後も `make test` がパスし続けること。

---

## 2. オニオンアーキテクチャの実装順序

TDD を適用する際、依存関係の下流（内側）から順に進めるのがスムーズです。各レイヤーの責務については、[README.md のアーキテクチャセクション](../../README.md#アーキテクチャ) を参照してください。

1. **Domain 層**: エンティティや値オブジェクトのロジックを TDD で実装。
2. **UseCase 層**: 抽象化されたリポジトリ等を使用してビジネスロジックを TDD で実装。
3. **Infrastructure 層**: 具体的な外部接続（DB, クリップボード等）の実装と統合テスト。
4. **Presentation 層**: UI (PySide6) の構築。

---

## 3. 品質ゲート (最終確認)

実装完了後、以下のコマンドでプロジェクト全体の整合性を確認します。

```bash
# リンター(Ruff) と 型チェック(Pyright) を実行
make check
```

- **型チェック**: `Pyright` でエラーが 0 であること。
- **スタイル**: `Ruff` のルールに適合していること。

---

## 4. 完了と記録

1. **Git コミット**: `git-commit-style-guide.md` に従い、日本語の Conventional Commits 形式でコミット。
2. **動作確認**: `make run` で実際のアプリケーションの動作を最終確認。
3. **リリース**: 必要に応じて `macos-app-release` ワークフローを実行。
