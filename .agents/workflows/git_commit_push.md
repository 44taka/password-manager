# 🌿 Git コミット & プッシュ・ワークフロー
// turbo-all

あなたはGitの専門家として、以下の手順で正確にコード変更を管理してください。

## 📋 手順

### 1. 変更状況の確認
1. `git status` を実行し、現在のステージング・未ステージングのファイルを把握します。
2. 未ステージングのファイルがある場合、ユーザーに「どの変更をコミットに含めるか」を確認してください。

### 2. コミット・フェーズ（繰り返し可）
1. `git --no-pager diff --staged` で**現在ステージされている内容**を確認します。
2. [.agents/rules/git_commit_rules.md](../rules/git_commit_rules.md) の規約に従ってコミットメッセージを作成し、`git commit -m "<メッセージ>"` を実行します。
3. コミット完了後、ユーザーに以下を確認してください：
    - 「他にも個別にコミットすべき変更はありますか？」
    - 「（未ステージングの変更がある場合）残りの変更もコミットしますか？」
4. 他にコミットすべき内容がある場合は、**手順1に戻って繰り返します**。

### 3. プッシュ・フェーズ
1. すべてのコミットが完了したら、現在のブランチ名を `git branch --show-current` で取得します。
2. `git push origin <現在のブランチ名>` を実行して、ローカルのコミットをまとめてリモートに反映します。

### 4. プルリクエスト作成（任意）
1. 現在のブランチが `main` ブランチ**以外**の場合のみ、ユーザーに「プルリクエストを作成しますか？」と確認してください。
2. 作成する場合は `gh pr create --fill` 等を用いて作成し、URLを報告してください。

## ⚠️ 注意事項
- 1つのコミットには「1つの論理的な変更」のみを含めるように心がけてください。
- プッシュ前に、意図しないコミット（デバッグ用のコードなど）が含まれていないか再確認を促してください。
- コンフリクトが発生した場合は、直ちに作業を中断し、ユーザーに報告してください。
